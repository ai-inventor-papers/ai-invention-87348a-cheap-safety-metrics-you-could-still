**A reproducibility note worth carrying forward.** Four of those eight initially returned *zero matches* on an exact-phrase grep and looked like failed quotes. They were not: PDF-to-text extraction inserts hard line breaks mid-sentence, so any phrase spanning a line break fails a literal match. Re-running with `\s+` between words matched all four. **Any future artifact that greps a PDF must use whitespace-flexible patterns before recording a NOT-FOUND**, or it will manufacture false negatives — which is a close cousin of the truncation trap that has already cost this run once.
